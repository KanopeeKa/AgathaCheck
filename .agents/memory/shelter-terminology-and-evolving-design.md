---
name: Shelter terminology and evolving design
description: Canonical wording and how to treat prior Operations Desk references during the screen-by-screen redesign.
---

Use **Shelter** as the canonical product term for the teal operational
experience. It includes fostering organisations, which should recognise
themselves within the Shelter model. “Organisation” in earlier UI and design
documentation is legacy terminology, not the current product-facing label.

**Why:** The product is now intentionally directed toward shelters and fostering
organisations, and the user is evolving the earlier Operations Desk references
screen by screen toward the approved plum/teal visual direction.

**How to apply:** Use Guardian (plum), Shelter (teal), and Account (neutral) in
new product copy and design decisions. Treat prior navigation and screen
references as candidates for deliberate revision rather than fixed constraints;
change them only in the agreed, screen-by-screen redesign work. Preserve
technical identifiers and data-model names until their migration is explicitly
scoped.
